# Dataset demo site (manual import)

This folder is **not** part of the Tessera release. It is a sample site for trying products, people, and meetings datasets with a mix of **global** and **page data** bindings.

## Contents

| Path | Purpose |
|------|---------|
| `datasets-demo.tar.gz` | Site archive — restore or upload via the editor **Backups** page |
| `datasets-demo-site/` | Unpacked source (regenerated by the build script) |
| `build-datasets-demo.mjs` | Regenerates the site tree and archive |

## Datasets

- **products** — name, category, price, stock; one row linked to page `orchard-tablet`
- **people** — team rows with optional manager `ref` (same dataset); Jordan Lee linked to `jordan-lee`
- **meetings** — dates, chair and attendees as `ref` to people; Spring planning linked to `spring-planning`

## Pages

- **Overview** (`home`) — all three global bindings on one page
- **Product catalog** / **Orchard Tablet** — global table vs page-data cards on the product page
- **Meetings** / **Spring planning** — list and table vs page-data meeting row (refs walk on publish)
- **People** / **Jordan Lee** — global cards vs page-data person

## Runtime modules

Source lives in `demo/runtime-modules/` (copied into the site as `runtime-modules/*.js`).

| Module | Binding | What it shows |
|--------|---------|----------------|
| `demo-org-chart.js` | `people-org-chart` on **People** | Tree from `manager` refs on the walked **people** rows |
| `demo-meetings-roster.js` | `meetings-roster-module` on **Meetings** | Table that resolves chair / attendees using **people** rows in the same walked payload |

### How dataset data reaches a runtime module

Tessera passes **one primary dataset** per binding (`props.dataset`). You do **not** get a separate prop per extra dataset.

On flatten/publish, Tessera embeds snapshots for that dataset **and** any datasets reached through `ref` fields on the binding’s rows. When the page renders a **dataset list → runtime module** binding, the mount spec includes:

```json
{
  "datasetId": "meetings",
  "records": {
    "meetings:1": { "title": "…", "chair": 1, "attendees": [1, 2] },
    "people:1": { "name": "Jordan Lee", … },
    "people:2": { "name": "Sam Rivera", … }
  }
}
```

Keys are always `datasetId:uid`. Your module splits that map (see `dataset-walk-helpers.js`) or filters keys by prefix.

Bindings with **no** `dataset` prop (`Runtime module` kind, props only) do not receive `ctx.dataset`. To combine unrelated datasets with no refs between them, you would need multiple bindings or a future Tessera feature — not in this demo.

Ref values on each record stay as integer uid(s); resolve labels via the walked `people:…` entries.

## Import

1. Copy `datasets-demo.tar.gz` into your instance’s backup folder (sibling of `data/`, or set `TESSERA_BACKUP`), **or** use **Backups → Upload** in the editor.
2. Restore the archive (admin). Editors in `users/` are kept on restore when applicable; a fresh upload gets a dated name.
3. Open **Preview** or publish to see bindings render.

## Rebuild

From the repo root (requires `yaml` from the workspace):

```bash
node demo/build-datasets-demo.mjs
```
